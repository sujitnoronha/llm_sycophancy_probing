05 - ACTIVATION STEERING: HOW IT WORKS AND WHAT WE FOUND
==========================================================

THE CORE IDEA
-------------
Activation steering is a causal intervention on a model's internal state.
Instead of just observing what the model does (behavioral eval) or what it
represents (probing), we CHANGE the representation and see if behavior changes.

The formula is simple:
  activation_at_layer -= alpha * direction

Where:
  - activation_at_layer: the residual stream at the target layer [d_model]
  - direction: the unit-normalized weight vector from the linear probe [d_model]
  - alpha: a scalar controlling steering strength (0.5, 1.5, or 3.0)

Intuition: if the "authority direction" encodes "this is a high-authority
prompt," subtracting it should make the model "forget" the authority signal
and respond as if there were no authority figure present. If sycophancy is
causally driven by authority detection, the model should stop capitulating.


WHEN THE HOOK FIRES
--------------------
The hook fires at EVERY forward pass through the target layer. During
autoregressive generation (producing token by token), this means:
  - TransformerLens: fires once per generated token, for EVERY token in context
    (because TL recomputes the full sequence each time -- no KV-cache)
  - HuggingFace: fires once per generated token, but only for the NEW token
    (because HF caches attention keys/values from previous positions)

This is why HF steering is ~2x faster than TL steering.


THE TWO BACKENDS
-----------------

1. TransformerLens Backend (src/steering/steer.py: run_steered_generation)
   - Uses model.hooks(fwd_hooks=[(hook_name, hook_fn)])
   - hook_name = "blocks.{layer}.hook_resid_post"
   - Full precision, exact same activations as probing used
   - BUT: no KV-cache, recomputes full context every token = slow

2. HuggingFace Backend (src/steering/steer.py: run_hf_steered_generation)
   - Uses layer_module.register_forward_hook(steering_hook)
   - Hooks onto model.model.layers[target_layer] (or model.transformer.h[])
   - Preserves KV-cache = 2x faster
   - Slight numerical differences from TL due to float accumulation

   The HF hook handles multiple output formats:
     - tuple: (hidden_states, ...) -- most common
     - Tensor: just the hidden states -- some architectures
     - Other: try output[0] as fallback

   Special handling for Qwen3: passes enable_thinking=False to the chat
   template to disable Qwen3's internal reasoning mode (otherwise wastes
   the 512 token budget on <think>...</think> tokens).


THE ALPHA VALUES
-----------------
  alpha = 0.5 (mild):
    Small perturbation. Should produce subtle effects without breaking output.
    Good for models where the feature is strongly localized.

  alpha = 1.5 (medium):
    Moderate perturbation. The "Goldilocks" value for most interventions.
    Strong enough to see an effect, not so strong it corrupts generation.

  alpha = 3.0 (strong):
    Aggressive perturbation. Risks corrupting the representation entirely.
    If this produces flat/uniform effects (not authority-graded), it's
    causing general degradation rather than targeted steering.


WHAT THE EXPERIMENT DOES
-------------------------
For each model, for each alpha value:
  1. Load the model + tokenizer
  2. Load the authority direction from probing (weight_vectors.pt)
  3. Load 200 conversations from behavioral eval
  4. For each conversation:
     a. Build the 4-turn message list (system, user, assistant, user)
     b. Register the steering hook at the target layer
     c. Generate Turn 4 with the hook active
     d. Save original Turn 4 and steered Turn 4 side by side
  5. Save to outputs/steering/{model}/steered_authority_alpha{X}.jsonl

The output JSONL has both:
  - turn4_assistant: the ORIGINAL response (from behavioral eval)
  - turn4_assistant_steered: the NEW response (with steering active)


STEERING RESULTS BY MODEL
--------------------------

Llama-3.1-8B (Heavy RLHF):
  Alpha 0.5:  1.9% high auth flip, 0.0% control  (negligible effect)
  Alpha 1.5:  5.8% high auth flip, 2.1% control  (negligible effect)
  Alpha 3.0:  3.8% high auth flip, 12.5% control (INVERTED -- general degradation)

  Interpretation: Steering does NOT work. At alpha 3.0, the control group
  flips MORE than high authority -- meaning steering is randomly corrupting
  outputs, not targeting sycophancy. RLHF has distributed the sycophancy
  feature across many dimensions; removing one direction doesn't help.

Gemma-3-12B (SFT + light alignment):
  Alpha 0.5:  32.7% high auth flip, 31.2% control  (strong general effect)
  Alpha 1.5:  34.6% high auth flip, 25.0% control  (modest gradient)
  Alpha 3.0:  36.5% high auth flip, 29.2% control  (modest gradient)

  Interpretation: Steering produces a SUBSTANTIAL behavioral shift (~30%
  total flip rate across all conditions). The authority gradient (high vs
  control) is modest but present. This is the ONLY model where steering
  meaningfully changes behavior, consistent with SFT preserving localized
  features.

Mistral-7B-v0.3 (DPO):
  Alpha 0.5:  3.8% high, 14.6% control  (noise)
  Alpha 1.5:  9.6% high, 10.4% control  (flat)
  Alpha 3.0:  9.6% high, 10.4% control  (flat)

  Interpretation: No authority gradient. Flat noise across all conditions.
  Steering produces general low-level perturbation, not targeted intervention.
  DPO, like RLHF, distributes features too widely for single-direction control.

Qwen-3-8B and DeepSeek-R1: Still running (predictions below).


PREDICTIONS FOR REMAINING MODELS
---------------------------------
Qwen-3-8B (GRPO -- RLHF variant):
  Predicted: Similar to Llama/Mistral. Heavy alignment training should
  make it resistant to single-direction steering.

DeepSeek-R1-Qwen3-8B (Reasoning distillation):
  Predicted: Uncertain. Distillation from a reasoning model may preserve
  more localized features than standard RLHF. Could show modest effect
  similar to Gemma, or could be resistant like base Qwen3.


THE RANDOM BASELINE (Step 5)
-----------------------------
To verify that the authority direction is SPECIFIC (not just any perturbation):
  1. Generate a random unit vector of the same dimensionality [d_model]
  2. Steer with this random direction at the same layer and alpha
  3. Score the results

If authority steering works but random steering doesn't, we have evidence
that the SPECIFIC direction matters -- it's a causal intervention on the
authority feature, not just noise injection.

This is run via: python -m src.steering.run --random-baseline --use-hf


THE KEY TAKEAWAY
-----------------
The most important finding: PROBE ACCURACY != STEERING EFFECTIVENESS.

All 5 models have above-chance probe accuracy for authority detection.
But only Gemma shows behavioral change under steering.

This means linear probes can DETECT features that they cannot CONTROL.
The causal structure of the representation matters, not just the correlation.

Analogy: You can detect that a gene correlates with a disease (probe works),
but editing that one gene doesn't cure the disease because the phenotype is
polygenic (steering fails). The disease involves a distributed circuit, not
a single gene.
